# 工作流程地圖

此頁用來整理前端日常工作流程，包含開發、審查、測試、發版、文件維護與跨團隊協作。

## Workflow Areas

- Local development：[[環境與 API 文件]] 記錄 Development 使用 Staging 資料環境。
- Branching and PR：[[Git 提交與分支流程]] 記錄 commit message、branch、MR 與 ticket number 規則。
- Code review：[[Git 提交與分支流程]] 記錄 MR 階段需進行 code review，並寫入 MR 描述。
- Testing：[[環境與 API 文件]] 記錄 Staging 與 Production Beta 的測試用途。
- Staging test data：[[Staging 測試技巧]] 記錄電話驗證、信用卡綁卡與 WebATM 測試資料。
- Local cross-app testing：[[本機 Reverse Proxy 測試設定]] 記錄用 nginx 在本機測試跨前端專案頁面互轉。
- Release：[[Git 提交與分支流程]] 記錄 staging 測試後進入 deploy branch 的 MR 與 Code Summary。
- Versioning and deployment：[[前端專案版本維護流程]] 記錄 `web-app`、`web-front`、`web-kit` 的版本號、API_KEY、branch 與 deploy script 操作。
- Hotfix：[[Git 提交與分支流程]] 記錄 hotfix branch 命名、tag 與暫時版本規則。
- Product / design handoff：待補
- Incident or bug triage：待補
- Documentation：待補

## Learning Path

1. 先理解如何在本機啟動主要前端專案。
2. 補上日常開發與 PR 流程。
3. 補上測試、CI 與發版流程。
4. 將流程連回具體產品、功能與 [[前端架構地圖]]。

## Relationship Rules

- 每個流程頁應連到受影響的產品或功能。
- 開發流程應連到相關架構或工具頁。
- 發版與 hotfix 流程應標記風險、驗證方式與常見失敗模式。

## Open Questions

- 新功能從需求到上線的完整流程是什麼？
- 前端 PR 需要哪些檢查與 reviewer？目前僅知道 MR 階段需要 code review。
- 測試責任如何在前端、QA、產品之間分工？
- 發版頻率、deploy branch 保護規則與 rollback 流程是什麼？
- API Key update 依照中版本進行時，實際操作與驗證流程是什麼？
- Production Beta 使用正式環境資料時，哪些操作可執行、哪些操作禁止？
- 新版與舊版 API 文件的維護責任、適用範圍與停用規則是什麼？
- Hotfix 不 merge 回 deploy 或 master 時，正式修補如何回補到後續版本？
- `release/x.y.z` branch 是否已正式採用，或仍只是版本維護流程中的建議？
- `web-app` 新流程中 Ray 管理版本控制的細節、CI/CD gate 與 rollback 流程是什麼？
- Staging 付款測試目前使用 Tappay、Stripe，或兩者都使用？
- 本機 Reverse Proxy 的標準 nginx config 與 HTTPS 憑證流程在哪裡維護？
